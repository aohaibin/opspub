## 需求描述

优化 AI 助手聊天中的命令安全处理，解决当前“白名单外命令全部直接拒绝”的问题。目标是让 AI 可以正常回答普通问题和执行受控只读技能；对未命中极高危规则的改动生成结构化人工审批；对极高危命令永久拒绝；所有执行经过后端策略复核、审计和后置健康验证。

本任务覆盖：

- 命令与参数、目标路径的语义分析；
- 重定向、管道、命令替换、`find -exec`、`xargs`、Base64 等语法风险识别；
- 未解析变量和动态路径的静态标准化；
- AI 技能到结构化操作计划的编排；
- 非极高危改动的人工审批；
- 多服务器爆炸半径、灰度执行和失败停止；
- 执行后的健康验证；
- 审批生命周期、跨菜单待办通知和审计闭环。

---

## 方案设计

### 最终方案

采用 Rust 后端统一策略引擎，React 负责展示和交互，SQLite 持久化规则、计划、审批批次和审计状态。

```text
聊天请求
  -> 技能匹配与 Action Plan
  -> 命令静态标准化
  -> 参数/路径/语法风险分析
  -> 黑名单与服务器策略判断
  -> 直接执行或生成审批批次
  -> Rust 终检（哈希、锁、策略、有效期）
  -> 执行
  -> 后置健康验证
  -> 不可篡改审计
```

### 风险等级

| 等级 | 处理方式 |
|---|---|
| 极高危 | 永久拒绝，不生成审批单 |
| 高危 | 强制人工审批，可配置双人审批 |
| 中危 | 普通人工审批 |
| 低危只读 | 受控白名单内自动执行 |
| 低危改动 | 按服务器策略自动执行或审批 |
| 无法解析 | 不执行，要求补充信息或人工确认 |

### 安全边界

- 白名单是受控模板动作，不是泛命令放行。
- 黑名单规则按风险等级处理；只有极高危规则永久拒绝。
- 命令标准化只做静态解析，禁止为了展开变量而执行原命令。
- 模型不能直接输出并执行任意 Shell/PowerShell 文本。
- 审批批准后仍由 Rust 后端重新校验，前端不能改变审批命令。
- 灰度验证通过后，剩余服务器不能默认自动执行，必须在审批时明确授权。
- 单人主密码 + 冷静期属于应急降级，不等同于双人审批，且不能绕过极高危规则。

## 关键决策

- **架构归属**：策略和安全判断全部在 Rust Service 层；Command 只负责 IPC 参数校验；React 只负责展示和交互。
- **数据库**：继续使用 SQLite/rusqlite，按 `PRAGMA user_version` 递增迁移。
- **状态管理**：审批和批次事实状态保存在 SQLite；Zustand 只保存跨页面展示状态。
- **事件机制**：使用 Tauri Event 推送长任务和审批状态，页面卸载时清理监听器。
- **命令执行**：禁止前端直接执行命令；禁止把模型返回文本直接交给 SSH。
- **Capabilities**：优先复用现有 IPC、存储和日志权限；新增插件权限前单独评估作用域。

## 当前问题记录

### 问题 1：非白名单改动全部被直接拒绝

- **发现时间**：2026-11-03
- **影响范围**：AI 助手聊天和审批流程
- **根本原因**：`CopilotService::safe_chat` 目前只有 `restart_nginx` 进入审批，其他改动直接返回 `policy_guard: blocked`。
- **解决方案**：引入风险分级策略；非极高危且无法自动执行的改动生成结构化审批，不再统一返回白名单错误。
- **状态**：🟡 进行中

### 问题 2：前端黑名单没有成为后端执行前的统一规则

- **发现时间**：2026-11-03
- **影响范围**：安全页面、AI 聊天、审批执行
- **根本原因**：部分黑名单规则保存在前端配置中，Rust 执行路径没有统一复核。
- **解决方案**：规则迁移到 Rust/SQLite 策略引擎，前端仅作为管理和展示入口。
- **状态**：🟡 进行中

## 验收标准

- [ ] 普通运维问答不会被错误提示为白名单拒绝
- [ ] 只读模板动作可以自动执行并写入审计
- [ ] 非极高危改动可以生成审批卡片

- [ ] 多机操作默认支持灰度，并在验证失败后停止批次
- [ ] 执行后必须展示健康验证结果
- [ ] 审批过期、锁定、策略变更和命令篡改都会被后端拒绝
- [ ] 切换菜单或重启应用后，待审批状态可恢复
