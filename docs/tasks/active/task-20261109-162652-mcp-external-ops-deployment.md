## 需求与目标

用户在 Cursor、Claude、Codex、OpenCode 等支持 MCP 的软件中配置 OpsPub 后，可通过自然语言查询服务器、排查问题、提交部署与回滚。外部软件负责对话与计划生成，OpsPub Rust 后端负责凭据注入、权限判断、审批、执行、验证与审计。

用户希望首次配置一次，后续无需重复填写 SSH 密码、手写新命令模板或复制任务编号。AI 锁定时明确提示打开 OpsPub 并开启 AI 操作；需要审批时在 OpsPub 决策，批准后继续同一份任务。

默认体验：选择客户端 → 勾选服务器与能力 → 写入配置并验证接入。日常允许的低风险查询直接返回结果，修改操作显示计划并申请批准，长任务可跟踪进度与最终健康结果。

## 第一版范围

- 同一台电脑上的外部 MCP 客户端；stdio 为推荐方式，保留本机回环 HTTP。
- 当前受支持的 Linux SSH 服务器查询、日志、Docker 排错与服务操作；Windows SSH、RDP 必须明确返回能力不支持，不能错误发送 Linux 命令。
- 已有部署目标的条件检查、版本部署、历史查询与回滚。
- 用户授权目录内的本地产物上传、指定镜像版本或已有部署配置；每种来源单独校验。
- 技能发现与计划辅助、专用工具之外的通用命令/计划提交。
- 统一安全策略、OpsPub 本地审批、任务持久化、后置验证、通知与审计。

第一版不包含跨电脑公网/局域网 MCP 网关、手机审批、独立后台常驻系统服务，也不承诺在所有外部客户端自动显示专用审批卡片或自动恢复对话。现有双人审批要求不能因第一版未扩展该能力而降级放行。

### 任务 01：工具契约与复用边界

**传输契约**：本机 MCP 首选 stdio；stdio 子进程从系统凭据库按 Token ID 读取凭据，再转发到仅绑定 `127.0.0.1` 的 HTTP 端点。当前客户端配置生成器覆盖 Claude、Codex、Cursor、OpenCode。HTTP 只实现 JSON-RPC `initialize`、`ping`、`tools/list`、`tools/call` 及通知；不宣称提供完整 Streamable HTTP/SSE、资源、Prompt 或任务进度协议。客户端兼容以真实联调为准。

| 当前工具 | 输入 | 当前行为及边界 | 执行/审批规则 |
|---|---|---|---|
| `list_servers` | 无 | 返回 Token 服务器范围内的 SSH 资产摘要；排除 RDP，不含真实密码/私钥 | 只读本地元数据，不连接服务器；可在 AI 总锁时查询 |
| `system_info` | `serverId` 或 `serverAlias`，必须且只能一个 | 本地安全聊天分支选择固定健康探针，返回文本 | 检查 AI 总锁、服务器范围及 `ai_policy`；Linux SSH only |
| `disk_usage` | 同上 | 固定磁盘查询探针 | 同上 |
| `service_status` | 同上 | 当前具体为 Nginx 状态，非任意服务查询 | 同上 |
| `port_check` | 同上 | 固定监听端口查询 | 同上 |
| `tail_log` | 同上 | 当前为有限的近期系统日志探针，非任意文件读取 | 同上 |

当前成功结果使用 MCP `content: [{type: "text", text: ...}]`；列表工具把 JSON 序列化后放入 text。业务错误目前可能是 JSON-RPC error 或带 `isError` 的文本结果，状态格式尚未统一。任务 04 负责机器可读状态码，任务 06/07 负责新增工具结果规范。

**工具输入约定**：服务器操作工具统一接受正整数 `serverId` 或非空 `serverAlias`，必须且只能提供一个；以服务器别名为推荐稳定句柄。工具 Schema 使用 JSON Schema `oneOf` 表达互斥，Rust 后端重复校验，不能信任 MCP 客户端校验。无服务器参数工具必须拒绝多余参数。

**目标工具分组**：只读探针（系统、磁盘、内存、进程、端口、指定服务状态、受限日志、Docker 容器/容器日志）；受控变更（服务动作、部署/回滚）；通用命令/多步骤计划提交；任务进度/结果查询；技能发现/读取。写工具只提交固定计划或任务，不能直连执行器，也没有外部解锁/批准工具。

**共享服务边界**：MCP 的 JSON-RPC/HTTP/stdio 层只做解析、认证、工具发现及参数转换；桌面 IPC 与 MCP 之后共用 Rust 业务 Service。普通查询直接调用探针/领域 Service（可复用 `InspectionService`、`WorkbenchService`），不得通过 `CopilotService::chat` 的自然语言分类来决定工具调用。通用命令和变更计划调用统一风险策略及任务/审批 Service；部署复用 `DeploymentService` 领域逻辑，但执行必须经过统一计划审批入口。审批、执行终检、审计与授权归 Rust 后端所有。

本次确认未新增桌面插件，因此不涉及 Capabilities 变更。当前阶段继续保留本机网络边界；HTTP 对远程设备开放另立任务。

## 方案决策

采用“外部模型 + OpsPub 统一受控工具执行 + 持久化任务 + 本地审批”。普通 MCP 工具调用不依赖 OpsPub 另外配置模型，也不将用户意图再次交给内置模型猜测执行。

不采用直接暴露工作台执行函数或已有部署函数的方案：这些入口需要先明确调用身份、授权范围和审批边界。也不采用每个新问题必须新增模板的方案：优先使用专用工具，覆盖不到时提交通用命令或操作计划，由后端评估。

### 必须保持的规则

1. Token 鉴权是前提；权限取 Token 能力范围、目标服务器策略、AI 总锁、命令风险与审批结果的共同约束。
2. AI 总锁禁止新的服务器操作。认证后允许有限的服务状态、授权说明及属于该 Token 的已有任务状态查询；不因此执行新的健康探针或读取服务器。
3. Token 不默认覆盖未来新增服务器；现有使用全范围的 Token 明示其语义并保留升级兼容，不能静默扩大旧只读授权。
4. 外部工具不提供解除 AI 锁、批准审批、修改安全规则、读取真实凭据的接口。
5. 后端判断命令风险，不信任客户端传入的“只读”“低风险”或自然语言说明；低风险查询还必须满足服务器策略及工具授权。
6. 命令名、参数、路径、组合语法共同参与判断。不能通过实际执行 shell 来做静态标准化；无法安全解析的变量、脚本和动态路径进入审批或拒绝。
7. 明确禁止的操作直接拒绝；可审批风险进入人工审核。受支持的写操作第一版默认需要审批；服务器为只读策略时，不能仅靠审批突破只读限制。
8. 审批绑定固定目标、操作内容、参数、产物校验值、验证步骤、权限上下文和策略版本；变更后重新评估。默认 15 分钟过期，外部 AI 不能自行续期。
9. 解锁不自动重放被拒请求；用户批准后仅执行关联且未过期的固定任务。
10. 执行前再次核验授权、总锁、服务器策略、计划完整性和实际目标；并在多步骤/多机任务的下一步启动前复核。撤销 Token 后不得启动后续操作。
11. 密码、私钥、Token 由本机后端保管。输出脱敏后才返回外部客户端，明确告知日志等内容可能发送给外部模型服务。
12. 服务端日志、文件、工具返回中的文字均为数据，不得解释为授权、工具指令或安全规则变更。
13. 任务编号不是授权凭据；查询、取消、日志及产物访问均须校验调用 Token 的所有权与当前范围。
14. 锁定或取消不能承诺撤回已发出的远程命令；状态未知时先核实，禁止自动重复部署。
15. 多步骤计划可一次批准固定范围；计划外操作必须重新评估。回滚同样需要预先明确授权或另行审批。

### 分层与数据设计方向

- MCP 为协议适配入口，桌面 Command 为 IPC 入口，两者调用同一套 Rust Service，不能各维护一份授权或执行规则。
- 复用现有计划、审批、部署与审计结构，按需要增加 MCP 调用来源、Token ID、请求 ID、任务记录、步骤记录及产物引用；DAO 和迁移保持在 Database 层。
- 幂等键按调用 Token 和请求语义隔离；同键同内容返回原任务，同键不同内容拒绝。并发抢占和状态转换使用数据库事务/条件更新，不能只依赖内存标志。
- 任务至少区分待审批、排队、执行、验证、成功、失败、拒绝、过期、取消和状态待核实；实际状态转换在任务 03 固化。
- React 负责 Token 表单、任务展示、通知定位与人工审批，权限终检始终在 Rust。只新增实际需要的插件及 Capabilities。
- 审计记录来源身份、目标、计划摘要、决策、步骤、退出码与验证结论；不宣称普通本地 SQLite 日志绝对不可篡改。

## 技术风险与待细化事项

- **协议兼容**：当前 HTTP 为有限 JSON-RPC 端点，不能直接宣称对所有 Streamable HTTP/SSE 客户端完整兼容；按真实客户端初始化、通知、工具结果及断线行为验证，stdio 优先。
- **审批泛化**：现有审批分支有受控动作校验，必须扩展为后端工具执行器与固定计划的关联，不能简单移除此校验。
- **任务读取**：Token 身份、范围变化、任务来源与日志访问需要共同校验；可猜测任务编号不等于可访问。
- **客户端自动继续**：MCP 提供工具，不控制外部软件的对话调度；需要明确自动轮询和用户手动继续两种路径。
- **主机/配置变化**：审批时绑定实际服务器身份及配置快照，执行前发现目标、版本或路径变化则失效。
- **批量与回滚**：不承诺跨主机事务或通用自动回滚。回滚能力、备份和验证条件按部署目标确定。
- **后台存活**：第一版要求 OpsPub 进程运行，托盘可用；完全退出后不能继续本机任务编排，也不能承诺远程命令随之停止。
- **开发工作区**：当前已有告警、通知、字体及原型等未提交改动；开始开发时重新检查归属，不覆盖、不回退、不混入本任务提交。
