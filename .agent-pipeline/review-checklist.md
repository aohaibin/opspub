# OpsPub 新版双轨工作区通用验收清单

以 `docs/ops-prototype-direction2-workspace.html` 为界面交互基准，以改造前实际可用的行为和已保存数据为功能基线。每次先读实现方的变更范围、验证日志与截图，再查有区分度的反例，记录能核对的复现步骤、实测结果和证据路径。推理结论标记为「未验证」。

- [ ] **导航**。17 个模块从新版导航可达。跨页直达和前进、后退后，一级业务域、二级高亮、顶部标题与页面一致。
- [ ] **原型与窗口**。对照布局、字号、间距、字段顺序、表格、按钮、弹窗、抽屉和交互状态。Windows 默认及最小允许窗口在亮色和暗色下检查滚动、溢出及底部操作按钮。保存关键页面截图与对应原型截图。
- [ ] **二级栏联动**。验证服务器分组或标签、终端会话、SFTP 连接、数据库节点与右侧内容同步，收起再展开后保留选择。
- [ ] **功能回归**。逐项验证服务器新增、编辑、导入，终端，SFTP 上下载，工作台，数据库连接、查询、导出，批量部署，AI 对话审批，MCP、技能、巡检、告警、审计、凭据和设置。以实际接口返回和可见结果为证据，检查失败提示。远程验证遵循仓库的操作授权规则。
- [ ] **会话和旧数据**。验证服务器直达终端、SFTP、工作台的目标一致性，切页恢复会话，后台上传持续。使用隔离副本检查旧版本保留的资产、凭据引用、数据库配置、AI 历史和设置。涉及真实资料时，在隔离副本操作并核对原文件。
- [ ] **审批与审计**。验证 AI 锁定、审批通过、拒绝、超时及审计记录。数据损坏、安全、凭据、真实计费和核心流程不可用均为阻断项。
- [ ] **整体验收**。收齐逐步验证日志。整体验收执行 `pnpm build`、`cargo check`、`cargo test`，走查 Windows 打包应用并保留逐模块通过状态、证据和缺口。验收环境不足的条目标记「未验证」，记录原因。

启动验证使用项目任务系统。先查已登记任务，必要时扫描、登记和启动。前端修改使用热更新，构建配置、环境或依赖变更后重启。Tauri 的 Rust 修改等待热编译和真正的桌面窗口。临时任务用完从任务系统停止。

每次回报写明结论（通过、阻断或建议否决）、实际检查与证据、阻断项、非阻断项和需决策事项。验收会话只负责检查和回报，提交由实现方在总控裁决通过后执行。
