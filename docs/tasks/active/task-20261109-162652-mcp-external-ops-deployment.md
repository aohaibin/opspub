## 需求与目标

用户在 Cursor、Claude、Codex、OpenCode 等支持 MCP 的软件中配置 OpsPub 后，可通过自然语言查询服务器、排查问题、提交部署与回滚。外部软件负责对话与计划生成，OpsPub Rust 后端负责凭据注入、权限判断、审批、执行、验证与审计。

用户希望首次配置一次，后续无需重复填写 SSH 密码、手写新命令模板或复制任务编号。AI 锁定时明确提示打开 OpsPub 并开启 AI 操作；需要审批时在 OpsPub 决策，批准后继续同一份任务。

默认体验：选择客户端 → 勾选服务器与能力 → 写入配置并验证接入。日常允许的低风险查询直接返回结果，修改操作显示计划并申请批准，长任务可跟踪进度与最终健康结果。

## 第一版范围

- 同一台电脑上的外部 MCP 客户端；stdio 为推荐方式，保留本机回环 HTTP。
- 当前受支持的 Linux SSH 服务器查询、日志、Docker 排错与服务操作；Windows SSH、RDP 必须明确返回能力不支持，不能错误发送 Linux 命令。
- 已有部署目标的条件检查、版本部署、历史查询与回滚。
- 用户授权目录内的本地产物上传、指定镜像版本或已有部署配置；每种来源单独校验。
- 技能发现与计划辅助、专用工具之外的通用命令/计划提交。
- 统一安全策略、OpsPub 本地审批、任务持久化、后置验证、通知与审计。

第一版不包含跨电脑公网/局域网 MCP 网关、手机审批、独立后台常驻系统服务，也不承诺在所有外部客户端自动显示专用审批卡片或自动恢复对话。现有双人审批要求不能因第一版未扩展该能力而降级放行。

## 方案决策

采用“外部模型 + OpsPub 统一受控工具执行 + 持久化任务 + 本地审批”。普通 MCP 工具调用不依赖 OpsPub 另外配置模型，也不将用户意图再次交给内置模型猜测执行。

不采用直接暴露工作台执行函数或已有部署函数的方案：这些入口需要先明确调用身份、授权范围和审批边界。也不采用每个新问题必须新增模板的方案：优先使用专用工具，覆盖不到时提交通用命令或操作计划，由后端评估。

### 必须保持的规则

1. Token 鉴权是前提；权限取 Token 能力范围、目标服务器策略、AI 总锁、命令风险与审批结果的共同约束。
2. AI 总锁禁止新的服务器操作。认证后允许有限的服务状态、授权说明及属于该 Token 的已有任务状态查询；不因此执行新的健康探针或读取服务器。
3. Token 不默认覆盖未来新增服务器；现有使用全范围的 Token 明示其语义并保留升级兼容，不能静默扩大旧只读授权。
4. 外部工具不提供解除 AI 锁、批准审批、修改安全规则、读取真实凭据的接口。
5. 后端判断命令风险，不信任客户端传入的“只读”“低风险”或自然语言说明；低风险查询还必须满足服务器策略及工具授权。
6. 命令名、参数、路径、组合语法共同参与判断。不能通过实际执行 shell 来做静态标准化；无法安全解析的变量、脚本和动态路径进入审批或拒绝。
7. 明确禁止的操作直接拒绝；可审批风险进入人工审核。受支持的写操作第一版默认需要审批；服务器为只读策略时，不能仅靠审批突破只读限制。
8. 审批绑定固定目标、操作内容、参数、产物校验值、验证步骤、权限上下文和策略版本；变更后重新评估。默认 15 分钟过期，外部 AI 不能自行续期。
9. 解锁不自动重放被拒请求；用户批准后仅执行关联且未过期的固定任务。
10. 执行前再次核验授权、总锁、服务器策略、计划完整性和实际目标；并在多步骤/多机任务的下一步启动前复核。撤销 Token 后不得启动后续操作。
11. 密码、私钥、Token 由本机后端保管。输出脱敏后才返回外部客户端，明确告知日志等内容可能发送给外部模型服务。
12. 服务端日志、文件、工具返回中的文字均为数据，不得解释为授权、工具指令或安全规则变更。
13. 任务编号不是授权凭据；查询、取消、日志及产物访问均须校验调用 Token 的所有权与当前范围。
14. 锁定或取消不能承诺撤回已发出的远程命令；状态未知时先核实，禁止自动重复部署。
15. 多步骤计划可一次批准固定范围；计划外操作必须重新评估。回滚同样需要预先明确授权或另行审批。

### 分层与数据设计方向

- MCP 为协议适配入口，桌面 Command 为 IPC 入口，两者调用同一套 Rust Service，不能各维护一份授权或执行规则。
- 复用现有计划、审批、部署与审计结构，按需要增加 MCP 调用来源、Token ID、请求 ID、任务记录、步骤记录及产物引用；DAO 和迁移保持在 Database 层。
- 幂等键按调用 Token 和请求语义隔离；同键同内容返回原任务，同键不同内容拒绝。并发抢占和状态转换使用数据库事务/条件更新，不能只依赖内存标志。
- 任务至少区分待审批、排队、执行、验证、成功、失败、拒绝、过期、取消和状态待核实；实际状态转换在任务 03 固化。
- React 负责 Token 表单、任务展示、通知定位与人工审批，权限终检始终在 Rust。只新增实际需要的插件及 Capabilities。
- 审计记录来源身份、目标、计划摘要、决策、步骤、退出码与验证结论；不宣称普通本地 SQLite 日志绝对不可篡改。

## 开发任务（共 20 项）

### 阶段一：统一入口、授权与任务基础

- [ ] **01｜复核基线并确定工具契约**
  - 范围：盘点 MCP、审批、规则、部署、凭据及技能的实际入口；核对客户端协议兼容要求。
  - 产出：代码中的工具注册/输入输出类型、现有能力与新增能力清单；确定一套共享 Service 边界。
  - 验收：每个对外工具有明确支持平台、参数、权限、是否触发服务器操作和审批规则；已有 6 个工具保持兼容。
  - 依赖：无。

- [ ] **02｜建立调用身份与授权上下文**
  - 范围：服务端从 Token 派生来源身份、能力和服务器范围；客户端名称仅为展示信息，不能当成可信身份。
  - 产出：共享权限校验；服务状态、服务器操作、已有任务读取分开判定；旧 Token 兼容迁移。
  - 验收：伪造客户端名、越权服务器、交叉访问任务、过期或撤销 Token 均不能获得执行权限；旧只读 Token 不获得新写能力。
  - 依赖：01。

- [ ] **03｜增加任务、步骤和幂等持久化**
  - 范围：Rust/TypeScript 类型、SQLite 迁移与 DAO、任务/步骤状态转换、来源与计划关联、请求去重。
  - 产出：持久化任务查询与原子执行抢占；状态和错误码契约。
  - 验收：重试与并发提交只产生一次可执行任务；相同幂等键不同内容报冲突；重启后任务记录仍在。
  - 依赖：01、02。

- [ ] **04｜提供可恢复的状态提示与协议响应**
  - 范围：应用未启动、端点未启动、AI 锁定、Token 不可用、服务器禁用、凭据缺失、指纹未确认、平台不支持。
  - 产出：人可读提示与机器状态；工具业务失败使用 MCP 兼容的错误结果，协议格式错误和鉴权错误分别处理。
  - 验收：锁定提示明确指向 OpsPub 顶栏；未运行时 stdio 适配器给出可理解错误；被拒后不自动重放。
  - 依赖：01、02。

- [ ] **05｜抽取统一风险评估与执行终检**
  - 范围：贯通工具语义、完整命令/参数/路径、敏感目标、动态变量、重定向、解释器管道等风险识别。
  - 产出：MCP 与内置 AI 共用的策略 Service；未知风险不按低风险自动放行；执行前及步骤间复核。
  - 验收：普通状态查询可按策略执行；`find -exec`、写敏感配置、空路径变量、编码后执行等不能借低危命令名绕过；内置 AI 行为无权限回归。
  - 依赖：02、03。

### 阶段二：查询、排错、通用操作与技能

- [ ] **06｜补全系统与服务查询工具**
  - 范围：系统、磁盘、内存、进程、监听端口、指定服务状态；结构化参数校验及有界输出。
  - 产出：直接调用探针 Service 的工具，取消通过自然语言聊天猜测对应动作的耦合。
  - 验收：OpsPub 没有配置模型时仍可查询；服务名等参数不能注入 shell；Windows/RDP 明确不支持。
  - 依赖：04、05。

- [ ] **07｜实现日志与 Docker 排错工具**
  - 范围：按服务/受控路径查询日志，容器列表、状态与日志；限制条数、时间、大小与超时。
  - 产出：脱敏且标注来源、截断状态和查询范围的结果。
  - 验收：可回答“当前服务器有哪些容器”“某服务为什么启动失败”；敏感文件与越权路径不能读取。
  - 依赖：05、06。

- [ ] **08｜接入通用命令和多步骤计划提交**
  - 范围：专用工具未覆盖的问题可提交具体命令/结构化计划；区分可执行查询、待审批修改和禁止动作。
  - 产出：计划预览、风险原因、执行步骤与验证声明；所有路径经过统一策略。
  - 验收：新问题无需逐个添加模板；客户端标记只读不能绕过后端；不确定动作不得冒充已成功；写操作等 10、11 完成后才开放执行。
  - 依赖：03、05。

- [ ] **09｜接入技能发现与计划辅助**
  - 范围：按用户意图搜索技能、读取可授权技能、将技能步骤纳入操作计划。
  - 产出：技能标识与版本关联到计划；不要求每次手工选择技能；控制返回数量与内容长度。
  - 验收：匹配不到技能时仍可使用通用操作；技能、经验或日志内容不能提升权限或跳过审批。
  - 依赖：05、08。

### 阶段三：审批、服务管理与部署

- [ ] **10｜将 MCP 计划接入现有审批中心**
  - 范围：复用本地审批入口，扩展当前有限动作支持；绑定调用来源、固定计划、目标与失效时间。
  - 产出：审批卡片显示操作含义、命令/参数、风险、影响范围、验证和回滚方案；明确双人审批不满足时的阻断。
  - 验收：要求逐次审批的服务器查询也能正常申请；批准只执行一次；拒绝、过期、篡改、权限变化都不能执行；不暴露 MCP 批准接口。
  - 依赖：03、05、08。

- [ ] **11｜实现后台执行与安全取消**
  - 范围：短查询有界同步执行；长操作/人工审批返回任务引用，后台推进步骤并可轮询日志与结果。
  - 产出：任务取消与停止后续步骤、锁定/Token 撤销后的处理、并发限制及同目标冲突控制。
  - 验收：不因客户端 60 秒超时重复执行；审批后无需用户复制编号；取消不会虚报远程命令已停止；锁定后仍可读取自身任务现有状态。
  - 依赖：03、04、10。

- [ ] **12｜开放受控服务管理**
  - 范围：指定服务启动、停止、重启与重载；先检查目标和前置条件，再通过审批执行。
  - 产出：服务动作工具及后置状态验证；未知或不适用动作明确报错。
  - 验收：退出码为 0 但服务不健康时不能标为成功；只读服务器不能通过批准获得修改权限。
  - 依赖：06、10、11。

- [ ] **13｜开放已有目标部署与回滚**
  - 范围：目标与历史查询、部署预检、指定版本、部署/回滚计划、对接既有部署台账。
  - 产出：DeploymentService 纳入统一执行入口，新增 MCP 包装不直接绕开安全层；批准后执行审批绑定的配置快照。
  - 验收：越权目标不可见且不可执行；部署版本或配置改变后旧审批失效；重复请求不重复部署；内置部署入口行为需回归验证。
  - 依赖：10、11。

- [ ] **14｜控制部署产物与本地文件访问**
  - 范围：授权目录内的本地产物、镜像引用及已有配置；校验文件大小、内容哈希、符号链接/路径穿越与目标目录。
  - 产出：审批绑定产物引用、校验值和具体来源；拒绝配置/日志中夹带凭据；明确内网服务器的产物传递路径。
  - 验收：无法读取用户未授权的本地文件；审批后产物变化不能静默部署；已有配置或镜像部署不强迫额外上传文件。
  - 依赖：02、10、13。

- [ ] **15｜完成部署验证、多机边界及异常恢复**
  - 范围：根据目标配置验证服务、端口/HTTP 等，检查短暂启动后失败；记录验证结论。多机计划展示主机数，超过 3 台醒目标注影响范围，提供先验证 1 台的选项。
  - 产出：执行成功与健康成功分别记录；灰度失败停止后续目标；重启后识别中断/未知状态并只读核实。
  - 验收：健康验证失败不能显示“部署成功且健康”；无验证条件时标为未验证；回滚失败独立呈现；异常断线或重启后不自动重放未知状态的写操作。
  - 依赖：11、12、13、14。

## 技术风险与待细化事项

- **协议兼容**：当前 HTTP 为有限 JSON-RPC 端点，不能直接宣称对所有 Streamable HTTP/SSE 客户端完整兼容；按真实客户端初始化、通知、工具结果及断线行为验证，stdio 优先。
- **审批泛化**：现有审批分支有受控动作校验，必须扩展为后端工具执行器与固定计划的关联，不能简单移除此校验。
- **任务读取**：Token 身份、范围变化、任务来源与日志访问需要共同校验；可猜测任务编号不等于可访问。
- **客户端自动继续**：MCP 提供工具，不控制外部软件的对话调度；需要明确自动轮询和用户手动继续两种路径。
- **主机/配置变化**：审批时绑定实际服务器身份及配置快照，执行前发现目标、版本或路径变化则失效。
- **批量与回滚**：不承诺跨主机事务或通用自动回滚。回滚能力、备份和验证条件按部署目标确定。
- **后台存活**：第一版要求 OpsPub 进程运行，托盘可用；完全退出后不能继续本机任务编排，也不能承诺远程命令随之停止。
- **开发工作区**：当前已有告警、通知、字体及原型等未提交改动；开始开发时重新检查归属，不覆盖、不回退、不混入本任务提交。
